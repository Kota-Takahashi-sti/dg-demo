# 記録の定型化(build-log.md / PROGRESS.md)

CLAUDE.md の記録ルールの実装。**作業しながら随時追記**する(後でまとめて書かない)。
日付はすべて絶対日付(YYYY-MM-DD)。既存の記録を読み直す必要はない —
build-log.md は末尾に追記、PROGRESS.md は該当箇所のみ Edit する。

## build-log.md への追記テンプレート

該当する種別のものだけを使う。見出しレベルと体裁は既存エントリに合わせる。

### 設計判断

```markdown
### <判断の題名>(<フェーズ>、<YYYY-MM-DD>)

- **判断**: <採用した方式>
- **理由**: <なぜそれか>
- **不採用の代替案**: <案> — <不採用理由>(必ず書く。なければ「特になし」と明記)
```

### バージョン・公式ドキュメント調査

```markdown
### <製品名> バージョン調査(<YYYY-MM-DD>)

- 調査日: <YYYY-MM-DD> / 参照URL: <一次情報のURLを列挙>
- リリース状況: <最新安定版と根拠(GitHub Release / PyPI / Docker Hub)>
- 採用: <バージョン>(<ピン留め方法>)。<1つ前に落とした場合はその理由>
- 実装に効く要点: <API/構文の変更点など>
```

doc-researcher エージェントの返す「build-log 貼付用ブロック」はこの形式なので、
そのまま貼ってよい。

### 遭遇した問題(試行のたびに追記。30分または3回で停止し報告)

```markdown
### 問題: <現象の一行要約>(<フェーズ>、<YYYY-MM-DD>)

- **現象**: <エラーメッセージ・観測事実>
- **試行1**: <やったこと> → <結果>
- **試行2**: …
- **解決**: <最終的な解決方法と原因> / または **未解決**: 既知の制約として
  ガイドと本ログに明記した旨
```

## PROGRESS.md の更新(作業の区切りごと)

1. フェーズ表の「状態」を更新(未着手 / 作業中 / 完了報告済み / 差し戻し対応中)。
2. 「現在のフェーズの詳細タスク」のチェックボックスを実態に合わせる。
   完了した項目には証跡の場所(verification/phaseN/ 等)を含める。
3. 「次にやること(セッション再開時はここから)」を、**この会話の文脈なしで
   再開できる具体性**で書き直す。
4. 発注者に確認すべきことがあれば「未解決の問題・発注者への確認事項」へ。

## 完了チェック

- [ ] 相対日付(「今日」「昨日」)を書いていない
- [ ] 不採用の代替案を省略していない
- [ ] CLAUDE.md + plan.md + PROGRESS.md + build-log.md だけで再開できる状態になっている
